# Test Plan: TTFT-based client TPS

## Created
2026-09-14

## Goal
생성·최종 TPS가 요청 대기시간을 제외하고 첫 토큰 이후의 수신 구간을 측정하는지 검증한다.

## Environment
Windows, npm workspaces, Studio Docker, Chrome, http://localhost:43120/inference/query.

## Preconditions
기존 inference history를 보존한다. 실기 확인에는 모든 122B stage의 현재 load generation 응답과 SESSION 준비가 필요하다.

## Steps
1. timing 시험: TTFT 차이, 단일 토큰, 동시 수신, 요청 간 격리, 소수 시각, EOS, legacy 환산.
2. connection 시험: 모의 WebSocket의 합쳐진/분할 frame 수신 시각과 consumer 지연 격리.
3. typecheck/test/build, npm run deploy, published health 검사.
4. Chrome 새로고침 후 기존 요청 출력·토큰·TTFT 보존과 생성/최종 TPS 일치, 재새로고침 보존 확인.
5. 실제 에이전트 조회 후 가능하면 122B 새 질의의 TPS 확인. 조회 실패를 성공으로 승격하지 않는다.

## Expected Results
TPS=(N-1)*1000/(last-first); N<=1 또는 관측 구간 0이면 null. final TPS는 완료 시 확정. UI 발행 100ms, 저장 1초로 합쳐도 토큰 집계는 즉시 유지한다.

## Logs To Capture
시험 결과, deploy report, Chrome AX/screenshot, 실제 조회 실패 및 원격 포트 상태. 브라우저 수신 TPS와 엔진 처리량을 구분한다.

## Locator Contract
`모델` combo box, `질의` tab, `스트리밍 질의 결과` table, 안정적인 request ID를 포함한 행. Chrome AX 인덱스는 매 관측에서 갱신한다.
