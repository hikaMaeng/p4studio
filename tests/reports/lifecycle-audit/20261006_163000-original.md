# Lifecycle fixes: implementation and deployed Chrome verification

2026-10-06. 사용자 요청의 LOAD·SESSION·추론·중지·UNLOAD·복구·용량을 수정하고 공식 Docker 배포와 설치된 Chrome으로 검증한다. **Studio 국소 회귀와 TUF 실기는 별도 결과이며 MiMo100건, 공개 P4 관리 drain, 모든 host 수용을 자동으로 통과시키지 않는다.**

## Source and ownership

- Studio `main`, HEAD `6b83fd65609fbb39928557ae079838e2780a33c4`, dirty working tree. 이 보고는 HEAD만의 시험이 아니다. 모델 항목별 잠금·부재 뒤 fresh-generation LOAD 정책은 동시 진행한 작업의 변경과 함께 회귀한다.
- 참조 P4 HEAD `f2e019b0fcd825c38c29924e562a8341e3918ccd`, 다른 작업의 native speculative 코드 변경은 이 작업의 구현으로 집계하지 않는다. TUF 실제 바이너리는 host proof의 SHA256으로 결속하며 현재 P4 HEAD 빌드라고 주장하지 않는다.
- Studio branches: local `main`, remote `origin/main`. worktree `F:/dev/p4studio` 하나. 삭제 전 bundle·dirty checkout·남은 디렉터리는 `F:/dev/p4studio-backups/20261006-lifecycle-audit/`에 보존했다. 별도 P4/NDX 저장소의 다른 작업은 삭제하지 않았다.

- 원래 OUTER를 잃은 요청에 대한 공개 P4 native/KV 관리 drain은 미지원이다. 승인 Windows force recovery는 정상 CANCEL·RELEASE 또는 정상 UNLOAD 성공의 대체 영수증이 아니다.
