## Failures and evidence boundaries
Early browser-script failures were fixture timing/setup issues: lazy Markdown needed an explicit content wait, and the init script reset the locale on reload. Corrected and reran all scenarios. `evidence/failure.png` retains the initial diagnostic screenshot and is not acceptance evidence. Docker mechanical checker previously emitted `check name=owned:docker/Dockerfile status=violation detail=dockerfile-not-under-apps-service-docker` and `check name=exists:docker/Dockerfile status=violation detail=referenced-dockerfile-missing`; it ignores Compose build context. Resolved Compose config actually uses `apps/studio` plus `docker/Dockerfile`, and official image build/deploy succeeded. No Docker contract change was made for those false positives.

Browser checks use completed fixtures in isolated localStorage and do not create GPU inference, agent operations or DB mutations. Existing fleet/M42 evidence belongs to its original reports; this UI change does not re-certify it. P4 files were not modified or published.
